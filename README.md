# FraudDesk

An interactive simulation of a bank fraud operations queue.

Most fraud detection demos stop at the model. Real fraud teams spend their days inside the queue the model creates: alerts arriving faster than analysts clear them, most of them false alarms, each one costing real review time. FraudDesk simulates that queue. One day of synthetic transactions replays through a scored triage stream while a small analyst pool works it, and the counters show what the operation costs as it runs.

**Live demo:** [au5100.github.io/frauddesk](https://au5100.github.io/frauddesk/)
**Plain language overview, use cases and integration notes:** [docs/OVERVIEW.md](docs/OVERVIEW.md)

## What it shows

- A streaming triage queue with per alert reason codes in plain language
- Queue depth, oldest alert age against a 30 minute SLA, and estimated review cost per hour
- A rule layer on top of the score: transactions meeting the MAS Shared Responsibility Framework rapid draining definition are held regardless of model score
- A methods panel stating exactly what is synthetic, what is a cited industry estimate, and what is placeholder

## Honesty notes

All transactions are generated by a seeded script in this repository. No real data, no downloads, no accounts. The current risk score is a transparent heuristic and says so in the app. The generator stores a hidden outcome label for future evaluation work and the scorer never reads it. Cost and false positive figures are industry estimates from cited sources, not invented precision.

## Roadmap

```
npm install
npm run dev
```

The bundled dataset is committed. Regenerate it with `npm run generate-data`.

## Stack

Vite, React, TypeScript, IBM Carbon (g100). Static site, no backend, no keys.
